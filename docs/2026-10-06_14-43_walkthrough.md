# Reporte de Entrega (Walkthrough): Corrección de Document Root en Plesk

**Fecha y Hora**: 2026-10-06 14:43  
**Módulo**: Configuración de Hosting Plesk (`Hosting Settings`, `docs/despliegueEnPlesk.md`)  
**Problema**: En la pantalla de Hosting Settings de Plesk se configuró `Document root = mandala.axiacorehub.com/dist`, impidiendo la ejecución del backend Node.js (`server.js`) y evitando que la aplicación reconozca el archivo `.env`.

---

## 1. Causa Raíz Identificada en la Captura

En la captura de pantalla de **Hosting Settings** para el subdominio `mandala.axiacorehub.com`:
- **Document root configurado:** `mandala.axiacorehub.com/dist`

### ¿Por qué esto causa el fallo de `.env` y de la IA?
1. **Plesk trata el sitio como estático plano:**
   Al apuntar el `Document root` a `dist`, Apache/Nginx sirve directamente el contenido de `dist/` (HTML, CSS, JS estáticos compilados por Vite) sin invocar Node.js ni Phusion Passenger.
2. **`server.js` queda inactivo:**
   El archivo ejecutable del backend ([server.js](file:///Users/francisco/Herd/Mandala-Copilot/server.js)) no se ejecuta. Las llamadas a las rutas `/api/*` (como `/api/gemini-status`) devuelven error 404 o el HTML de la página.
3. **El navegador no lee `.env`:**
   Los navegadores web no leen archivos `.env` en disco por seguridad. Quien lee `.env` es `server.js` en Node.js. Al no estar corriendo `server.js`, las variables `GEMINI_API_KEY` y `GEMINI_MODEL` nunca se cargan.

---

## 2. Solución Requerida en Plesk

1. **Ajustar Document Root en Hosting Settings:**
   - Cambiar de: `mandala.axiacorehub.com/dist`
   - A: `mandala.axiacorehub.com`
2. **Verificar la pantalla de Node.js en Plesk:**
   - **Application Root:** `mandala.axiacorehub.com`
   - **Application Startup File:** `server.js`
   - **Document Root:** `mandala.axiacorehub.com`
   - **Node.js:** Habilitado / Activado.
3. **Ubicación de archivos:**
   - En la carpeta `mandala.axiacorehub.com/` deben estar:
     - `server.js`
     - `package.json`
     - `.env`
     - Carpeta `dist/` completa
4. **Reiniciar Aplicación:**
   - Presionar **"Reiniciar aplicación"** (*Restart*) en Plesk.
